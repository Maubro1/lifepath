# Life-long map: level-of-detail lines

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The map shows every trip ever recorded at every zoom level and time filter, fast, by drawing simplified per-trip lines when zoomed out and full points only when zoomed in. Replaces the temporary 200 000-point cap.

**Architecture:** Trips get a small cache row each (time span, bounding box, distance, a coarse simplified line with per-vertex speed), built by the smoothing service (open or charging only) and rebuilt for trips it re-smooths. The map picks the cache for zoomed-out views and full points for zoomed-in views.

**Spec:** `docs/superpowers/specs/2026-11-14-lifepath-design.md` — "Principles" 1 (life-long and complete), 7 (cool and light), "Screens" Map bullet.

## Global Constraints

- Principle 1: no recorded trip may be missing from the map at any zoom or time filter. Reduce detail, never coverage.
- Cool phone: cache building only while open or charging; nothing renders off screen.
- Stored points never modified; the trip cache is derived and recomputable.
- Ponytail; Core imports Foundation only; Diary imports GRDB + Core.
- Release: version 0.2.1 build 6, tag `v0.2.1-preview.1`.

## Review Focus

1. A trip whose cache row is missing or stale (recorded since the last smoothing run) must still appear (fallback: full points for trips after the cache's coverage end).
2. Time filter edges: a trip crossing the filter boundary is included.
3. Zoomed-out "All" with years of synthetic data stays within a fixed vertex budget and never hits the old cap.
4. The cache stays consistent after re-smoothing overlap (seam) — no duplicate trips.
5. Upgrading from v0.2.0 with an empty trip cache: the first run fills it; meanwhile the map still shows everything (fallback).
