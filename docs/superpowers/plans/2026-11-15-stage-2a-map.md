# Stage 2a: Map Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The owner sees their recorded life on a map: trips drawn as clean lines (offline-smoothed where available), coloured by date or speed, filtered by time, with a heat view and a locate-me button.

**Architecture:** New pure Core pieces (trip segmentation, Douglas–Peucker simplification, a Rauch–Tung–Striebel trip smoother, a time-weighted heat grid) with tests; a Diary v2 migration that stores the Doppler course for future smoothing and caches smoothed points; a smoothing service that only runs while the app is open or the phone is charging; a Map tab built on a wrapped `MKMapView`.

**Tech Stack:** Swift 6.2, SwiftUI, MapKit (`MKMapView`, `MKPolyline`, `MKGradientPolylineRenderer`, custom `MKOverlay`), GRDB, BackgroundTasks.

**Spec:** `docs/superpowers/specs/2026-11-14-lifepath-design.md` (sections "Filtering and smoothing" item 5, "Screens" Map bullet, "Cool phone", "Bad signal", "Ways of moving"). Learned places are stage 2b.

## Global Constraints

- Core imports Foundation only; Diary imports Foundation, GRDB, Core; no new dependencies.
- Swift tools 6.2, platforms `.iOS(.v26), .macOS(.v15)`; bundle ID unchanged.
- Stored points are never modified. The smoothed cache is derived and recomputable (replace on recompute is allowed).
- Cool phone: smoothing and other heavy work run only while the app is open or the phone is charging; the map renders only while on screen; no work in the background on battery.
- Ponytail: smallest complete change; no abstraction nobody asked for.
- Local Core tests: `pwsh -NoProfile -File scripts/test-core.ps1`; CI is the gate (`bash scripts/ci-wait.sh <sha>`); repo is public, fixtures synthetic only.
- Release: MARKETING_VERSION 0.2.0, build 5, tag `v0.2.0-preview.1`.

## Review Focus

1. A trip that spans a long gap (tunnel, phone off, app killed) must never be smoothed or drawn as one straight line across town. (Task 1 `testGapSplitsTrip`, Task 2 `testSmootherNeverBridgesTrips`)
2. Points recorded before this version have no course: the smoother must still work (position only) and not crash on mixed data. (Task 2 `testNoCourseFallsBackToPositionOnly`, Task 4 `testOldRowsReadCourseAsInvalid`)
3. "All time" on years of data must not freeze the UI: queries limited to the visible region, simplification per zoom, work off the main thread. (Task 6)
4. Smoothing must not run in the background on battery. (Task 5)
5. Still points must not draw as lines or scribbles: a rest is a dot, not a pacing pattern. (Task 1 `testStillPointsAreNotTrips`)

**Interfaces (Produces):**

```swift
public struct Trip: Sendable, Equatable { public var points: [FilteredPoint]; public var start: Date; public var end: Date; public var distance: Double /* m */; public var movingTime: TimeInterval }
public enum Trips { public static func split(_ points: [FilteredPoint], maxGap: TimeInterval = 600, maxJump: Double = 500) -> [Trip] }   // moving points only; a still point, a gap > maxGap or a jump > maxJump ends a trip; trips with < 2 points dropped
public enum Simplify { public static func douglasPeucker(_ coords: [(lat: Double, lon: Double)], tolerance: Double /* m */) -> [Int] }   // indices kept, first and last always kept
```

### Task 2: Trip smoother (Core)

**Files:** Create `Core/Sources/Core/TripSmoother.swift`; Test `TripSmootherTests.swift` (reuse `Synthetic.swift`)

**Interfaces (Produces):**
```swift
public struct RawFix: Sendable, Equatable { public var t: Date; public var lat, lon, hAcc, speed, course: Double }   // speed/course < 0 = invalid
public enum TripSmoother { public static func smooth(_ fixes: [RawFix]) -> [(t: Date, lat: Double, lon: Double)] }   // one trip; same count and order as input
```
Rules: forward constant-velocity Kalman per axis in metres (same model as TrackFilter's calm model: qa from the trip's median valid speed — < 2.5 m/s → 1.0, < 7 → 2.0, else 4.0; position update with the 2.45σ linear-Huber gate; Doppler velocity update when speed ≥ 0, course ≥ 0, hAcc ≤ 20, R_v = 0.49 + (speed·σθ)², σθ 10° on foot / 3° vehicles), storing predicted and filtered states; then the Rauch–Tung–Striebel backward pass. O(n). No IMM, no consistency inflation (the backward pass replaces them).
- [ ] Failing tests (all with realistic Doppler from `Synthetic`, plus one without course): `testWalkMedianAtMost6mWithoutCourse` (σ 12 m, course −1 throughout) ≤ 6 m; `testWalkNotWorseThanLiveFilter` (same fixture as TrackFilter's walk test with realistic Doppler: smoother median ≤ live TrackFilter median); `testCornersWithin10m`; `testMultipathBurstBetterThanLive` (max deviation in the noisy-Doppler burst ≤ the live filter's); `testNoCourseFallsBackToPositionOnly` (mixed course/no-course fixes, no NaN); `testSmootherNeverBridgesTrips` (smooth only receives one trip; assert input/output counts and timestamps identical); `testSingleAndTwoFixTrips`. RED → GREEN; commit `Core: RTS trip smoother`.

### Task 3: Heat grid (Core)

**Files:** Create `Core/Sources/Core/Heat.swift`; Test `HeatTests.swift`

**Interfaces (Produces):**
```swift
public struct HeatCell: Sendable, Hashable { public var x: Int; public var y: Int }     // ~25 m cells in a Web-Mercator-like metre grid
public enum Heat {
    public static let cellSize: Double = 25
    public static func cell(lat: Double, lon: Double) -> HeatCell
    public static func center(of c: HeatCell) -> (lat: Double, lon: Double)
    public static func grid(_ points: [FilteredPoint]) -> [HeatCell: TimeInterval] }   // each point weighted by the time until the next point, capped (still 300 s, moving 60 s); last point gets 0
```
- [ ] Failing tests: `testNightAsleepCountsTimeNotPoints` (8 h of still points every 5 min in one cell → 8 h, not 96 × something), `testMovingCappedAt60s`, `testCellRoundTrip`, `testCellsAre25m`. RED → GREEN; commit `Core: heat grid`.

### Task 4: Course in stored points; Diary v2

**Files:** Modify `Core/Sources/Core/Types.swift` (`FilteredPoint.course: Double`, default −1 in init), `Core/Sources/Core/TrackFilter.swift` (set course from the sample when course ≥ 0 and hAcc ≤ 20, else −1), `Diary/Sources/Diary/Diary.swift`; Tests `TrackFilterTests.swift`, `DiaryTests.swift`

Decisions: migration `v2` adds nullable `point.course REAL`, an index on `point(lat, lon)`, and table `smoothedPoint(t REAL PRIMARY KEY, lat, lon)`. Old rows read `course` as −1.
**Interfaces (Produces):**
```swift
public func points(minLat: Double, maxLat: Double, minLon: Double, maxLon: Double, from: Date, to: Date) throws -> [FilteredPoint]
public func smoothed(from: Date, to: Date) throws -> [(t: Date, lat: Double, lon: Double)]
public func saveSmoothed(_ pts: [(t: Date, lat: Double, lon: Double)]) throws   // INSERT OR REPLACE (derived cache)
public func smoothedUntil() throws -> Date?   // latest smoothed t
```
- [ ] Failing tests: `testCourseSetOnlyWhenAccurate` (TrackFilter), `testOldRowsReadCourseAsInvalid` (v1 row written raw, read after migration), `testCourseRoundTrip`, `testPointsInBox`, `testSmoothedReplace`. RED → GREEN (Diary tests run on CI only); commit `Core/Diary: store course; diary v2`.

### Task 5: Smoothing service (app)

**Files:** Create `LifePath/Map/SmoothingService.swift`; Modify `LifePath/LifePathApp.swift`, `project.yml` (Info: `BGTaskSchedulerPermittedIdentifiers: [app.lifepath.LifePath.smooth]`, `UIBackgroundModes` += `processing`)

Decisions: `SmoothingService.run()` reads points after `smoothedUntil()` (minus 10 min overlap) up to now − 10 min, splits with `Trips.split`, smooths each trip with `TripSmoother.smooth` (mapping `FilteredPoint` → `RawFix` from raw lat/lon), saves with `saveSmoothed`. Runs at most once per foreground (scenePhase `.active`) on a detached low-priority task, and from a `BGProcessingTask` registered at launch with `requiresExternalPower = true` (scheduled whenever the app goes to background). Logs one event `smooth` with detail `trips=N points=M` per run. Never runs on battery in the background.
- [ ] Implement; CI build green; commit `App: smoothing service (open or charging only)`.

### Task 6: Map tab (app)

**Files:** Create `LifePath/Map/MapScreen.swift` (SwiftUI screen + controls), `LifePath/Map/TrackMapView.swift` (`UIViewRepresentable` around `MKMapView`), `LifePath/Map/HeatOverlay.swift`; Modify `LifePath/LifePathApp.swift` (root after onboarding becomes a `TabView`: Map, Settings)

Decisions:
- Time filter: Today, Week, Month, Year, All, Custom (two date pickers); default Today.
- Lines: for the visible region (padded 20%) and time range, load points off the main actor, split with `Trips.split`, use the smoothed cache where it covers a trip's timestamps, otherwise the recorded `lat/lon`; a "Recorded line" toggle forces recorded. Simplify each trip with `Simplify.douglasPeucker` at tolerance = max(3 m, metres per screen point × 2).
- Colour: by date (one colour per trip from a blue→orange gradient across the selected range) or by speed (`MKGradientPolylineRenderer`, bands: walk < 2.5 m/s, bike < 7, drive ≥ 7).
- Map style: standard / satellite (`MKStandardMapConfiguration` / `MKImageryMapConfiguration`).
- Heat: toggle; `Heat.grid` over the time range, rendered by a custom `MKOverlayRenderer` drawing cells with alpha ∝ log(1 + seconds), capped at the visible region.
- Still points: never part of lines; shown as small dots only at street zoom.
- Locate me: `MKUserTrackingButton`; `showsUserLocation` only while the screen is visible.
- Rendering only while visible: data loads on appear / region change (debounced 300 ms) / filter change; nothing runs when the tab or app isn't visible.
- Plain system styling; the design stage restyles it later. Accessibility labels on every control.
- [ ] Implement; CI build green; commit `App: map tab`.
